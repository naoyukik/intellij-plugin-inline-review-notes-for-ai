# GitHub Issue 6: RangeMarker による編集時の行追跡

## 概要

コードの編集で行が増減しても、インラインレビューコメントの対象範囲を追跡する。ファイル保存時には追跡後の行番号を現在のブランチの `.inline-review-notes/{branch}.json` へ反映する。

## 機能要件

- コメントの作成時とファイル読込時に、対象 `Document` 上の `lineStart`／`lineEnd` に対応する範囲を `RangeMarker` で追跡する。
- 同一ファイルを保存すると、未解決・解決済みを問わず、そのファイルの全コメントを追跡位置から更新する。
- 範囲の削除などでマーカーが無効になったコメントは削除しない。直近の保存済み行番号を保持し、`isOutdated` を `true` にする。
- 解決済みコメントは Inlay を表示しないが、位置追跡と保存同期の対象とする。
- `isOutdated` の UI 表示は本トラックの対象外とし、未解決の outdated コメントは従来どおり表示する。
- 既存 JSON に `isOutdated` がない場合は `false` として読み込めるようにする。

## 非機能要件

- 既存の Kotlin パッケージ構成と、UI・ストレージ・モデル・起動処理の責務分離を維持する。
- JSON の読み書きは `ReviewCommentStorage` に集約する。
- 保存処理は対象プロジェクトと対象ドキュメントに限定する。
- 新規コードはユニットテストと統合テストで検証し、テスト対象のカバレッジは 80% 以上を目標とする。

## 受入条件

- コメントより前の行を挿入または削除して保存すると、JSON の `lineStart` と `lineEnd` が追従後の位置になる。
- 複数行コメントの開始行と終了行が、範囲内の編集後も正しく保存される。
- コメントの対象範囲を削除して保存してもコメントは残り、`isOutdated` が `true` になる。
- 同一ファイルの複数コメントを保存すると、解決済みコメントを含めて一度に同期される。
- `isOutdated` を持たない既存 JSON を読み込むと、コメントは通常状態として扱われる。
- コメントの作成、編集、削除、再読込、およびブランチ別保存の既存動作を維持する。

## 対象外

- outdated 状態を視覚的に区別する UI。
- 列単位の範囲追跡。
- `.inline-review-notes/` の保存形式を JSON 以外へ変更すること。
- コメントのチーム共有、外部データベース、または新規 IntelliJ 拡張点の追加。
